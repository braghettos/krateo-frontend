# frontend CRDs (chart repo)

The CRDs the frontend owns ship from the **`crds-subchart/`** chart (`krateo-frontend-crd`,
`crds-subchart/Chart.yaml`), deployed as its own Composition independently of the app (see
[overview.md](overview.md)). This page is a **curated** field map — the authoritative, exhaustive
schema is the CRD YAML itself (`crds-subchart/templates/<Kind>.crd.yaml`), and the Go source of truth
is the code repo `braghettos/krateo-frontend`.

## What this repo ships — the widget CRDs

This chart owns **24** CRDs, all in group/version **`widgets.templates.krateo.io/v1beta1`** (each CRD
declares `served: true, storage: true` on `v1beta1`, e.g. `Button.crd.yaml:24,477-478`). They are the
declarative shape of every Composable Portal UI component. CRD subchart version: **`1.0.25`**
(`crds-subchart/Chart.yaml:20`), pinned independently of the app chart; generated by
`controller-gen` `v0.18.0` (`Button.crd.yaml:5`).

| Category | Kinds (plural) |
|----------|----------------|
| **Layouts** | `Page` (pages), `Row` (rows), `Column` (columns), `DataGrid` (datagrids), `Panel` (panels), `TabList` (tablists) |
| **Visuals** | `Button` (buttons), `ButtonGroup` (buttongroups), `Paragraph` (paragraphs), `Markdown` (markdowns), `YamlViewer` (yamlviewers) |
| **Charts** | `BarChart` (barcharts), `LineChart` (linecharts), `PieChart` (piecharts) |
| **Navigation** | `NavMenu` (navmenus), `NavMenuItem` (navmenuitems), `Route` (routes), `RoutesLoader` (routesloaders) |
| **Data / logic** | `Form` (forms), `Table` (tables), `EventList` (eventlists), `Filters` (filters), `FlowChart` (flowcharts) |
| **Builder** | `BlueprintBuilder` (blueprintbuilders) |

> **The widget DATA is not in these CRDs.** A widget CR is the *declarative shape* of a UI component;
> its DATA is composed and served at RUNTIME by snowplow's content API (over `/call`). These CRDs say
> *what* to render and *where to pull from*; snowplow resolves the actual content. The snowplow agent
> owns that runtime half (`braghettos/krateo-snowplow-chart`).

## The shared widget shape (`spec`)

Every widget CR follows the same `spec` contract (illustrated with `Button.crd.yaml`; the same keys
recur across all 24 — `widgetData`/`widgetDataTemplate`/`resourcesRefs`/`resourcesRefsTemplate` are
present in all 24 CRDs):

| Field | Type | Purpose |
|-------|------|---------|
| `widgetData` | object (**required**) | The component's static visual config/behaviour — label, icon, type, items, actions (`rest`/`navigate`/`openDrawer`/`openModal`), etc. The one required field (`Button.crd.yaml:155,470-472`). |
| `widgetDataTemplate` | []object | Overrides `widgetData` paths with dynamic values: `forPath` (dot-notation target) + `expression` (a JQ expression like `${ .results }`) (`Button.crd.yaml:461`). |
| `resourcesRefs` | object `{items[]}` | References to other resources/widgets used to compose the UI; each item carries `apiVersion`, `resource` (plural kind), `name`, `namespace`, `verb`, `id` (`Button.crd.yaml:57`). |
| `resourcesRefsTemplate` | []object | Populates `resourcesRefs` dynamically: an `iterator` (JQ over a result set) + a `template` rendered per element (`Button.crd.yaml:124`). |
| `apiRef` | object `{name, namespace}` | Reference to the RESTAction (snowplow) whose result feeds the templates (`Button.crd.yaml:47`). |

`status` is open on every CRD (`type: object`, `x-kubernetes-preserve-unknown-fields: true`,
`Button.crd.yaml:473-475`). Each CRD adds an `AGE` printer column.

### Actions (inside `widgetData`)

Interactive widgets carry an `actions` map under `widgetData` with keys `rest`, `navigate`,
`openDrawer`, `openModal`:

- **rest** — trigger an HTTP request on a `resourceRefId`: `{ id, resourceRefId, type: rest,
  payload, payloadToOverride }`, with `onSuccessNavigateTo` / `onEventNavigateTo` for follow-up.
- **navigate** — `{ type: navigate, url }`.
- **openDrawer** — `{ type: openDrawer, resourceRefId, size: default|large, title }`.
- **openModal** — `{ type: openModal, resourceRefId, title }`.

A `Button` fires its action via `widgetData.clickActionId` matching an action `id`.

## Notable kinds

- **`NavMenuItem`** is **mandatory** for surfacing a new portal section — it links a nav entry to a
  `Page`; `NavMenu` is the container.
- **`Route` / `RoutesLoader`** map URL paths to the resources/widgets that render them; routes are
  usually emitted by a `RoutesLoader` rather than hand-authored (the SPA bootstraps via the
  `INIT` + `ROUTES_LOADER` `/call` URLs in `config.json`, see [wiring.md](wiring.md)).

## Exhaustive detail

- **The CRDs themselves:** `crds-subchart/templates/<Kind>.crd.yaml` — the authoritative schema for

- **The Go source of truth:** the code repo `braghettos/krateo-frontend` — the widget Go types from
  which these CRDs are generated.
